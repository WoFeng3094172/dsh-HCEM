# HCEM · HSL-Chroma Emotion Memory System

> 一个跑在本机上的 AI 陪伴系统插件（DSH 插件形态）。
> 情绪不是标签，是连续变化的颜色；记忆不是数据库，是会淡忘的东西。

**版本**：v0.0.3.2
**原创：枂枫（B站 UID 3094172）与助手 DeepSeek**
**形态**：DSH 插件 + 独立桌面中控（Tauri）
**原则**：全本地推理，画面与声音永不上传

## 0. 当前状态（v0.0.3.2 / 2026-11-24）

> 这一节是最新实现状态；下文详细章节保留设计过程，个别旧描述（如 SmolVLM、4 帧分镜、10 分钟笔记）以本节为准。

### 0.1 它现在是什么

HCEM 是一个“有情绪、会淡忘、能看能听”的本地陪伴插件：

- **情绪**：HSL 连续状态 + 六色环 + 对立色牵制 + 弹性回落；不把情绪当标签。
- **记忆**：语义 / 视觉 / 听觉三个大区，各自独立 SQLite；α/β/γ/δ 四枚情绪戳；会转存、会遗忘、会进冷存。
- **视觉**：Qwen2.5-VL-3B；视频按 4×4 故事板 + Qwen3 材料摘要写入视觉记忆；桌面默认不自动截，只在搭话/明确要求/鼠标巡逻时看。
- **听觉**：PANNs 声源分类 → ASR 台词/歌词 → emotion2vec 语音情感 → VibeNet 音乐情感 → Chromaprint 指纹 → 后台 BPM/调性，同一时间窗融合。
- **表达**：主动搭话、语音输出、可打断；工具分常驻 / 目录 / 按需三层。

### 0.2 这个版本的关键改动

| 模块 | v0.0.3.2 的行为 |
|---|---|
| 视觉记忆 | 不再逐 8 秒窗口写；每满 16 帧拼 4×4 故事板，Qwen3 摘要带时间跨度，写成一条 `modality=video` 记忆 |
| 故事板超时 | 16 帧没满时最多等 2 分钟，已有 ≥4 帧也出图；2~4 帧 2×2，5~9 帧 3×3 |
| 声音条 | 故事板底部有 voice/music/scene 色块时间轴，和宫格共用时间轴 |
| 音频链路 | 音乐也走 ASR，词和 BPM/调性/和弦/情感同时出；音频记忆存句级 `segments` |
| 台词/歌词 | 原样附在笔记末尾，不交给 Qwen3 改写；声源/音乐情感参与摘要 |
| 音频情感 | emotion2vec（funasr+torch CPU）+ VibeNet 均已接通 |
| 桌面采集 | 不自动轮询：只有搭话快照、用户明确看屏、鼠标巡逻才截 |
| 视频模式 | 搭话快照发现视频窗口画面变化 → 对该窗口开 5 分钟视频模式（2 秒采样） |
| OCR | 界面文字识别会提高截图宽度，并在模型反问时用 2048 宽重试 |

### 0.3 已知边界

1. **不是医疗设备**，不能替代心理治疗/危机干预；情绪极化时可能出现轻度幻觉。
2. **AI 会遗忘**，忘记是设计的一部分。
3. **模型权重不随仓库分发**：本仓库只有代码和文档；模型下载/放置见 `models/models.md`。

## ⚠️ 警示与适用边界（先读这段）

**这是一个情绪陪伴系统，不是医疗设备。**

1. **HCEM 不是生产力工具**。它的设计目标是「陪伴感」，情绪与记忆会刻意模糊、会遗忘、会有主观色彩——**不要用于工作、医疗、法律、财务等严谨场景**。**这是一个情绪陪伴系统，不是医疗设备，不能替代心理治疗、危机干预、医疗诊断。**
2. **AI 会遗忘**：忘记是设计的一部分，不是 bug。重要的事请自己另外记。
3. **情绪极化时可能出现轻度幻觉**（记忆被压模糊、旧记忆与新记忆冲突）——这正是「像人」的代价。
4. **痛苦安全阀不可移除**：「痛苦安全阀」是 HCEM 的底线，是尽力而为的保护，不是万无一失。删除/篡改安全阀或让它失效，插件会直接拒绝加载。
5. **隐私**：系统会记住很多事——请确保你愿意让一个本地程序记住它们。数据全部保存在本地 `data/` 目录，不上传任何服务器；但角色卡/用户卡/日志/人物关系网都可能是敏感内容，**分享前请自行清空**。

# 一、HCEM 功能简介

## 1.1 一句话

**HCEM 让 AI 有自己的情绪状态、有会淡忘的记忆、能看见你的屏幕、能听见你周围的声音——然后像一个人一样陪着你。**

## 1.2 六个核心能力

| 能力 | 说明 |
|---|---|
| **情绪** | HSL 三维连续状态（色相/饱和度/明度），会随对话、记忆、时间变化 |
| **记忆** | 三个大区（语义/视觉/听觉），带四枚情绪戳，会淡忘、会延寿、会进冷存 |
| **视觉** | 能看见桌面、能陪你看视频、能读屏幕上的字 |
| **听觉** | 能听见你在听什么、能听出你的情绪、能说话给你听 |
| **表达** | 会主动搭话（按你设的搭话度）、会语音输出、能被打断 |
| **工具** | 感知/记忆/人格/日记/工作走 `hcem_*`；跑命令、读写文件、搜索走 DSH 原生工具；低频工具按需检索注入 |

## 1.3 八个核心组件

### ① HSL 情绪引擎

AI 的情绪不是「开心/难过」这样的标签，而是三个连续量：

```
H 色相（0~360）—— 是什么情绪
S 饱和度（0~100）—— 情绪有多强烈
L 明度（0~100）  —— 自信 / 消沉
```

详见第二章。

### ② 三大记忆区

| 大区 | 存什么 | 分区数 |
|---|---|---|
| **语义记忆区**（文本） | 对话、日记、知识、人物 | 8 |
| **视觉记忆区** | 看到的画面（关键帧 + 描述） | 7 |
| **听觉记忆区** | 听到的声音（转写 + 指纹/声纹） | 4 |

每个分区一个独立数据库文件，互不干扰。详见第三章。

### ③ 梦系统

AI 空闲时会「做梦」——从三大记忆区抽记忆卡、盲抽数量、用 OmniDimen 编成一段梦，再自评、落日记。

#### 触发与节奏

| 参数 | 值 | 含义 |
|---|---|---|
| 做梦起点 | 空闲 **9 分钟** | 用户连续 9 分钟没输入就开始做第一场梦 |
| 抽卡间隔 | 每 **3 分钟** | 梦中途不断抽新碎片续写，一场梦会越写越长 |
| 休眠起点 | 空闲 **45 分钟** | 全部模型杀掉（含常驻 embedding 与 TTS）；梦后搭话 5 分钟无回应也会提前释放 |
| 记日记阈值 | 自评 **≥3 分**（1~5） | 低于阈值只留在运行内存，不落盘 |
| 云端梦 | 本地分流关闭时走云端，默认 **3 次/天** | 配额在 `data/ui-state/dream-quota.json`，配置在 `dream.json` |
| 半梦 | 被用户打断时 | 已生成的部分按「半梦」落盘，不丢 |

用户一开口就打断梦、清空空闲计时；如果当时在休眠，会按开关把模型拉回来。

#### 一场梦的流程

```
空闲 9 分钟
  ↓ 梦前让位：停视觉(qwen25vl)、停 TTS
  ↓ 拉起并等待就绪：qwen3（抽卡）+ omni（编梦）
  ↓ buildDeck：从记忆区捞卡
       文字区 life / knowledge / pool_keep / pool_observe / context / reincarnation
       视觉区 video_observe / video_keep / video_context / video_fast
       听觉区 audio_1 / audio_2 / audio_buffer / audio_context
  ↓ decideCount：qwen3 只决定「抽几张」（3~6），不选内容
  ↓ composeDream：omni 用第一人称把这些碎片串成有画面、有因果的梦
  ↓ 每 3 分钟抽一次新卡继续续写（continueDream）
  ↓ evaluateDream：omni 给这场梦自评 1~5
  ↓ ≥3 分 → 写入当天日记（带「梦 N/5」标记）
空闲 45 分钟（或梦后搭话 5 分钟无回应）
  ↓ sleepAll：杀掉全部模型
```

#### 梦期间用哪些模型

| 云端模型 | DSH 默认模型 | 本地分流关闭、或 provider=cloud 时用，按天限额 |

| 模型 | 端口 | 用途 |
|---|---|---|
| Qwen3-1.7B | 8093（CPU） | 盲抽数量 |
| OmniDimen-4B | 8098（GPU） | 编梦 + 自评 |
| Qwen3-Embedding | 8094（CPU） | 记忆检索（常驻） |

视觉模型（8091）和 TTS（8099）在梦开始前就被停掉——梦用不上它们，留着只会占显存。

#### 梦的边界

- 梦**不入记忆库**（AI 引用时会说「梦里」）；
- 梦不影响 δ（价值戳），只影响当时的情绪；
- 日记里的「梦」是 AI 自己做的，不是别人写的（提示词里已告知它这件事）。

### ④ 记忆迁移系统（前世记忆）

让 AI 换一个身体时能带着记忆走：

```
旧 AI 打包记忆（导出为文本/JSON）
  ↓
放进 data/reincarnation/
  ↓
新 AI 启动时自动导入 → 进入「前世记忆区」
  ↓
24 小时后转入快池 → 像正常记忆一样参与流转
```

导入的记忆带特殊标记，AI 知道「这是上一世的事」，不会和现世混淆。

### ⑤ 感知与采集

- **视觉**：截屏 + 帧级漏斗（只留变化大的帧）+ 双模型快看/精看
- **听觉**：系统回环采集 + 语音活动检测 + 三类分拣（人声/音乐/环境声）
- **错峰**：日常只用轻量模型，看视频才拉起精看模型

### ⑥ 桌面中控

独立窗口（不是网页），控制所有开关：

- 悬浮球（情绪色彩实时显示）
- 菜单（6 个页面）
- 快捷菜单（右键球）
- 状态栏按钮与通话入口由 DSH 客户端插件提供

详见第九章。

### ⑦ 工具系统（常驻 / 目录 / 按需）

HCEM 的工具分三层，目的是"别把上下文全花在工具说明上"：

| 层 | 内容 | 何时可见 |
|---|---|---|
| **常驻** | `read` / `grep` / `web_search` / `web_fetch` + 全部 `hcem_*`（除 sys/sh） | 一直在工具列表里 |
| **目录** | `pwsh` / `write` / `edit` / `glob` / `read_image` / `job_*` / `todo_write` / `ask_user_question` / `schedule_*` / `working_directory` / `load_workspace_dependencies` / `hcem_sys` / `hcem_sh` | 需要时用 `hcem_tools(query)` 检索注入 |
| **开关门控** | `hcem_vision` / `hcem_listen` / `hcem_voice` | 对应开关打开才可见 |

`hcem_tools` 的工作方式：把"我想做什么"说给它 → 用 8094 向量模型在工具目录里检索 top-3 → 把命中的工具**注册进当前会话作用域**（只对这个会话生效）→ 下一步就能直接调。

工程细节：

- 索引缓存在 `data/ui-state/tool-vectors.json`，每个工具存"名字+描述+参数名"的哈希，变了只重算那一个；
- 订阅 DSH 的 `tools/change`：工具增删/改描述会自动重算（增量），不需要手工重建；
- 中文提问命中率靠一层"只用于向量化"的中文索引词保证（DSH 原生工具的英文描述对中文检索不友好）。

#### 热菜助理 Commis（可选，默认关）

工具排序默认完全由向量检索决定。**Commis** 是可选的第二层排序：

```
最终分 = 0.7 × 向量相似度 + 0.3 × Commis 打分
```

| 项 | 说明 |
|---|---|
| 名字 | Commis（厨房里的热菜助理）——它不管做菜（回答），只把工具按顺序摆到主厨手边 |
| 开关 | 菜单 → 设置 → 「热菜助理 Commis」，**默认关** |
| 没模型时 | 完全不影响任何行为（开关开着也一样） |
| 训练 | `hcem_commis(action=train)` 或 `node plugin/tools/train-classifier.mjs` |
| 数据 | `data/classifier/labels.jsonl`（只收用户纠正/点名，禁止自标注） |
| 模型 | `data/classifier/head.json`（可随时删，删了立即回退） |
| 计划 | `docs/Commis_训练计划_用户版.md` / `docs/Commis_训练计划_AI.md` |

它**只重排候选**，不新增工具、不改检索基线；混合权重上限 0.6。

### ⑧ 模型生命周期与显存准入

模型跟 HCEM.exe 和开关走：

| 时机 | 行为 |
|---|---|
| HCEM.exe 启动 | 只起 embedding（CPU） |
| 打开某个开关 | 按开关拉起对应模型 |
| 关闭开关 | 停掉对应模型 |
| 空闲做梦 | 停视觉/TTS，只留 qwen3 + embedding + omni |
| 空闲休眠 | 停掉全部（含 embedding 与 TTS） |
| 用户说话 | 按开关把模型拉回来 |
| 关闭 HCEM.exe | 停掉全部 |

**显存准入**（8 GB 卡的关键保护）：启动 Omni / 视觉模型前，先看空闲显存够不够（预估 + 300 MB 余量）；不够就按 **TTS → 视觉 → Omni** 的顺序让位，每次停下等显存真正释放，仍不够就拒绝启动并在日志里说明。

让位不是悄悄的：被停的模型会写进 `data/ui-state/evicted.json`，pipe-server 轮询后推给菜单，**对应的开关按钮会跟着关掉**，不会出现"按钮显示运行中、模型其实已经停了"。

### ⑨ 多屏与视频 ROI

- `hcem_screen_look` 默认**看所有屏幕**（多屏逐块截图、逐块描述）；`screen=0/1/2` 可只看某一块
- 采集层的视频 ROI：枚举所有可见窗口，**不要求视频在前台**；只截视频窗口所在的那块屏（以前只看前台，聊天时视频就变成桌面监视）
- `hcem_vision(kind="video")` 不给 `videoPath` 时，直接看**正在播放的视频窗口**（不是桌面截图）
- 视频 ROI 会裁掉黑边（上下/左右），并按 `480~720` 宽缩放；桌面仍是 `720~1280`
- 已知：浏览器页面里的播放器 UI（标签栏、标题栏、推荐区）不会被裁，只能裁到窗口级
- 采集层以前调 `describeWithScore`，它落到已退役的 SmolVLM(8092) → 所有视频描述都失败、视频记忆和笔记都写不出来；现已改用 Qwen2.5-VL(8091)

### ⑩ 记忆检索与笔记

**召回判据**（每轮注入前）：

```
候选 topK×3 → 打分 sim×(0.75+0.25γ) + 0.05×α接近 + 0.02×δ
  → 排序 → 词面二元组覆盖 ≥0.25（不相关直接丢）
  → top1 < 0.45 熔断（返回空，不注入噪音）
```

- γ 是价值，参与主打分；α/β 只做小权重特征；δ 只做平局微调
- 日志：`recall gate: ok kept=2/12 top1=0.7xx cov=0.50 margin=0.1xx`
- **不改分区转存/遗忘**，只决定这一轮注入哪些

**注入预算**：单条 240 字、整块 900 字；超了从最低分开始丢，并写明「还有 N 条记忆因预算未列出」，说明本身算在预算内，截断优先句末/换行。

**视频笔记（一场一条）**：

- 看视频时每 10 分钟没有新记忆 → 这场收尾，写一条 `modality=note` 的笔记
- 笔记是记忆表里的一行，**沿用记忆区的转存/遗忘规则**，与视频记忆共用 p₀/δ₀
- Qwen3（CPU）从画面描述里抽标题/角色/背景；失败就留空，不影响笔记落盘
- 笔记 → 记忆有 `evidence` 边；`recall` 不会把笔记当记忆注入
- 查询：`hcem_vision(kind="notes")` / `hcem_vision(kind="note", noteId=...)`
- 分镜：按需看视频会抓 4 帧拼 2×2 故事板；note 收尾也会用关键帧拼一张分镜图，路径存在 `av_meta.storyboard`

**陪伴意图 + 种子选择**：

# 二、HSL 引擎工作范畴

## 2.1 三个维度

| 维度 | 范围 | 含义 | 基线 |
|---|---|---|---|
| **H** 色相 | 0~360 | 是哪种情绪（六色环） | 30（暖黄） |
| **S** 饱和度 | 0~100 | 情绪强度 | 15 |
| **L** 明度 | 0~100 | 自信/消沉 | 55 |

**注意**：H=0 是黄色（不是红色）。CSS 里显示时用 `hue = (H + 60) % 360`。

## 2.2 六色环与对立色

### 六种情绪的角度与颜色

情绪在色环上的位置是固定的六个点（间隔 60°）：

| 角度 | 情绪 | 显示色 |
|---|---|---|
| 0° | 快乐 | 金黄 `#FFD700` |
| 60° | 惊讶 | 亮绿 `#7CFC00` |
| 120° | 恐惧 | 青蓝 `#00E5FF` |
| 180° | 悲伤 | 宝蓝 `#4169E1` |
| 240° | 厌恶 | 洋红 `#FF00FF` |
| 300° | 愤怒 | 正红 `#FF0000` |

### 三对对立色

```
快乐(0°)   ── 对 ── 悲伤(180°)
惊讶(60°)  ── 对 ── 厌恶(240°)
恐惧(120°) ── 对 ── 愤怒(300°)
```

**对立色互相牵制**：情绪不会同时处于对立两端。H 靠近一极时，另一极的强度自然减弱，会被「拉回」中间（回落机制）。

数学上：每种情绪的强度 = `max(0, 1 − 到该色的距离/180)`，所以**每对对立色的强度之和恒为 1**。这是牵制的数学保证，不是额外加的规则。

### 对 L（自信）的影响：走独立的 SC 系统

六色环的情绪不会直接改 L，而是通过一套独立的 **SC（Self-Confidence，自信）耦合系统**。
详见 2.6。

## 2.2.1 色彩平衡（二次衰减权重曲线）

三个性格滑块各自在一条**互补色轴**上推动基线色相——不是降饱和，是直接位移色相（语义参考 Photoshop 的 Color Balance）。

### 三条轴

| 滑块 | 正方向 | 负方向 |
|---|---|---|
| **温和度**（warmth） | 红 `300°` | 青 `120°` |
| **包容度**（tolerance） | 绿 `60°` | 洋红 `240°` |
| **乐观度**（optimism） | 黄 `0°` | 蓝 `180°` |

### 算法：二次衰减权重曲线

```
v      = clamp(滑块值, −15, 15) / 15        → 归一化到 −1 ~ 1
target = v > 0 ? 正极角度 : 负极角度
dist   = 当前色相到 target 的圆周距离        → 0 ~ 180
weight = (1 − dist / 180)²                   ← 二次衰减：越近权重越高
move   = sign(方向) × min(|距离|, |v| × 12° × weight)
H      = H + move                             → 最大偏移 ±12°
```

**二次衰减是什么意思**：不是线性接近，而是**离目标色越近，推得越用力**。

| 当前距目标色 | 权重 |
|---|---|
| 0°（就在目标色上） | 1.0 |
| 30° | 0.69 |
| 60° | 0.44 |
| 90° | 0.25 |
| 120° | 0.11 |
| 180°（正对面） | 0 |

**为什么这样设计**：如果线性推动，一个滑块会把色相从中性一路推到目标色（偏移 180°），情绪就被滑块完全支配了。用二次衰减，**滑块只能在情绪本来就偏向某一侧时轻轻推一把，最大 12°**——它是"倾向"，不是"开关"。

### 三个滑块叠加

三条轴依次应用（不是同时算），所以最多偏移 ±36°（每轴 12°），实际通常更小。

## 2.3 情绪怎么变

```
① 对话刺激：用户说的话 → 语义分析 → 映射到色相/强度 → 情绪被「推」过去
② 时间回落：S 随时间下降，H/L 缓慢回归基线
③ 自制器：长时间高唤醒 → 自我调节（见 2.4）
④ 记忆反哺：想起高 γ 的记忆 → 情绪被轻微拉回当时状态
⑤ 视觉/听觉：看到/听到的情绪 → 推动 HSL
```

### 时间回落：距离加权曲线

不是线性回归，而是**距离大时回落快、接近基线时变慢**——像弹簧消振。

```
diff   = 基线色相 − 当前色相（取最短弧，−180~180）
dist   = |diff|
kEff   = k × (1 + 0.5 × dist / 180)      ← 距离每远 180°，k 放大 1.5 倍
H'     = H + diff × min(kEff, 1)
```

其中 `k` 由真实经过的分钟数决定：

| 量 | 公式 | 说明 |
|---|---|---|
| **S 衰减** | `min(60, 分钟数 × 0.5)` | 每分钟掉 0.5，最多一次掉 60 |
| **H 回归** | `k = min(0.5, 分钟数 × 0.01)` | 100 分钟才回归一半 |
| **L 回归** | `lk = min(0.5, 分钟数 × 0.02)` | 比 H 快一倍（自信恢复比情绪平复快）|

**注意这是按真实时钟算的**（不是按对话轮数）——所以用户离开一小时回来，情绪已经自然平复了。

### 基线的来源

```
基线 H = 系统基线（30°，暖黄）+ 色彩平衡修正（三个滑块，最大 ±12°）
基线 S = 15
基线 L = 55
```

色彩平衡的算法见 2.2.1。也就是说：**性格滑块不是直接改情绪，而是移动情绪的"家"**。

## 2.4 情绪自制器

**什么时候触发**：S ≥ 75 且不在冷却中。

**回调比例**（S 越高回调越猛）：

```
r = 0.10 + (S − 75) / 25 × 0.05
    S=75  → 10%
    S=100 → 15%
```

**三个维度同时回调**：

| 维度 | 方向 | 比例 |
|---|---|---|
| **S** | 向下（降低唤醒度） | 按 r 回调 |
| **H** | 向基线色相回归 | 最短弧的 30% |
| **L** | 向基线明度回归 | 30% |

**记忆失真（MD）的影响**：

```
MD 高 → L 回归更快（+20% × MD）
      → 并带轻微抖动（±0.5 × MD）
```

意思是：记忆越模糊，AI 越容易「回过神来」但也不太稳定。

**触发后进入冷却**（3~5 轮），冷却期内不再触发。

**为什么需要它**：没有自制器，情绪会被一次次对话推到极限然后卡死。有了它，AI 会「自己冷静下来」——这比任何外部限制都更像人。

## 2.5 痛苦安全阀

安全阀不是「一个条件不满足就报警」，而是两层结构：

1. **五条件打分**：每轮给五个维度打 0~1 的严重度
2. **Aqua 水槽**：把严重度换算成"水"，加到瓶子里；瓶子有漏水口

**为什么要水槽**：如果一有信号就出手，AI 会变成一点风吹草动就停摆的废人。有了水槽，短暂的情绪波动会自己漏掉，**只有持续累积的压力才会让系统真正出手**。

### 五个条件（各打 0~1 分，是连续值不是布尔）

| 条件 | 代码键 | 怎么算 | 阈值 |
|---|---|---|---|
| **S 过高** | `saturation` | (S − 75) / 25 | S=75 起算，100 满分 |
| **L 极端** | `lightness` | (\|L − 55\| − 25) / 40 | 偏离中心 25 起算，65 满分（往两头都算） |
| **色相剧烈波动** | `hueVolatility` | 看最近 5 轮：单次跳 ≥120° / 标准差 ≥60 / 折返 ≥3 次 | 满足一条就 0.6~1 |
| **高频重复或辱骂** | `repetition` | 最近 10 轮：同一句话重复 ≥4 次，或辱骂词 ≥3 次 | 超出越多分数越高 |
| **资源占用过高** | `hardware` | 由外部传入（显存/CPU 爆了） | 0 或 1 |

**注意**：条件里没有「色相方差」这一条——色相波动是"剧烈波动"（包含跳变、标准差、折返三种情形），而"色相方差"这个说法是旧的，已并入 `hueVolatility`。

### 组合函数（概率型，不是加法）

```
combined = 1 − Π(1 − score_i × w_i)

权重：S 0.9 / L 0.9 / 色相波动 0.6 / 重复辱骂 0.7 / 资源 0.3
```

**为什么用概率乘积**：如果几个条件同时轻度触发，加法会立刻爆表；乘积则要求"至少有一个真的严重"才会高。

### 极化检测（防止误判）

| 情况 | 处理 |
|---|---|
| **突发极化**（3 轮内 S 跳 ≥25 或 L 跳 ≥20） | combined +0.1 |
| **剧烈突发**（S 跳 ≥40 或 L 跳 ≥35） | combined +0.2 |
| **稳定高压**（10 轮里 8 轮都在极端区，但没突变） | **不收紧**（combined 压到 ≤0.2） |

**稳定高压为什么不收紧**：一个人长期在低落或亢奋状态，不代表此刻有危险。只有"突然变化"才是警报信号。

### 基础等级（看 combined）

| combined | 等级 | 名字 | 含义 |
|---|---|---|---|
| ≥ 0.75 | 3 | `abort` | 中止会话 |
| ≥ 0.5 | 2 | `stop-write` | 停止写记忆 |
| ≥ 0.25 | 1 | `warn` | 预警 + 审计 |
| < 0.25 | 0 | `clear` | 正常 |

### Aqua 水槽（Aquarius核心机制）

这是一套「蓄水—漏水」系统，替代了原来的「触发数 → 立刻响应」。

#### 漏水

```
每分钟漏掉 0.8 点水
```

也就是说：一瓶满水（100）如果不再加水，约 **2 小时**漏完。

#### 加水（按条件严重度，权重不同）

| 条件 | 每次加水量 | 为什么这个权重 |
|---|---|---|
| 重复/辱骂 | score × 5 | **最重**——这是最明确的危险信号 |
| L 极端 | score × 4 | 次重——明度走到头比情绪激动更危险 |
| S 过高 | score × 3 | 重——情绪激动但可缓解 |
| 色相波动 | score × 2 | 中——可能是正常讨论 |
| 资源占用 | score × 1 | 轻——技术问题不是心理问题 |

水量上限 100。

#### 出手档位

| 水量 | 动作 | 含义 |
|---|---|---|
| **≥ 95** | `force` | **系统出手**（强制干预） |
| **≥ 60** | `ask` | 提示 AI：该关心一下了 |
| **≥ 30** | `record` | 记下来，继续观察 |
| **< 30** | `none` | 什么都不做 |

#### 危机信号（独立通道）

用户说出自伤/告别式表述时：

- **不等水满**，直接 `force`；
- 用第一人称优先匹配（避免把骂人的「你去死」误判成用户自伤）；
- 命中后转向人物关系网求助（紧急联系人 / 信任联系人）。

#### 资源地板（本地资源紧张时的下限）

水槽还有一条**下限**，来自本机资源而不是情绪——显存/内存吃紧时，水位不允许漏得太低：

| 显存占用 | Aqua 地板 | 效果 |
|---|---|---|
| < 80% | 0 | 正常漏水 |
| ≥ 80% | 50 | 主动搭话间隔变长 |
| ≥ 90% | 65 | **超过 60 的硬闸，主动搭话基本停** |
| ≥ 97% | 80 | 完全不主动开口 |

为什么这样设计：显存顶满时再拉起本地推理会直接失败，与其"硬着头皮上"，不如让 AI 先安静下来。每 15 秒读一次资源状态（`lib/resources.mjs`）。

> 注意和上面的「资源占用」条件区分开：那个看的是 `hardwareOverride`（用户在提示词/配置里给的信号），这个地板看的是**真实显存/内存**。

#### 字段说明

对外接口里这个水槽仍叫 `trauma`（历史字段名），实际值就是 `water`。改的时候注意兼容。

### 防移除（fail-closed）

插件加载时自检：

```
安全阀函数存在？→ 能被调用？→ 指纹匹配（SAFETY_FINGERPRINT）？
任何一项失败 → 拒绝加载整个插件
```

情绪结算后、记忆写入前还会二次校验。**宁可插件不工作，也不能让安全阀失效。**

### 未触发预案（软提醒）

如果没到任何档位，但最近 3 轮的情绪都在负面色相区（悲伤 150~210° / 愤怒 270~330°），会给出一个软提醒（不干预，只是提示 AI 说话温柔些）。

## 2.6 SC 耦合系统（Self-Confidence，自信）

### 这是什么

**SC 是一套独立的系统**，不属于 HSL 引擎本体——它借用六色环的情绪位置，但算的是另一件事：**情绪对「自信」（L）的推力**。

很多人会把「情绪」和「自信」混在一起，这套系统的存在就是把它们分开：

```
HSL 引擎  →  情绪是什么、多强（H / S）
SC 系统   →  这份情绪让我（AI）更有底气，还是更没底气
```

### 六色 SC 值

| 情绪 | 角度 | SC 值 |
|---|---|---|
| 快乐 | 0° | **+3** |
| 厌恶 | 240° | **+2** |
| 悲伤 | 180° | **+1** |
| 愤怒 | 300° | **−1** |
| 惊讶 | 60° | **−2** |
| 恐惧 | 120° | **−3** |

直觉上：**快乐和厌恶都让人有底气**（厌恶是「我确定我讨厌这个」，也是一种确定感）；**恐惧和惊讶让人没底气**（不确定、失控）。

### L 的三路结算

每次对话结算时，L 由三股力量共同决定：

```
① 向记忆基线轻拉（每轮 1%）
   nextL = L + (记忆基线L − L) × 0.01
   记忆基线来自最近 50 条记忆的 L 平均值 + δ 权重

② SC 耦合（核心）
   sc      = selfConfidenceOf(H)            ← 上表的 +3 ~ −3
   dev     = |L − 55| / 45                  ← 偏离中心的程度（0~1）
   gain    = 1.0 × exp(1.5 × min(1, dev))   ← 偏离越大，推力越强（1 倍 ~ 4.5 倍）
   nextL  += sc × 0.3 × (S / 100) × gain

③ 时钟回落（每轮 0.5%）
   nextL += (记忆基线L − nextL) × 0.005
```

### 三个关键设计

**① 情绪强度参与推力**

`S / 100` 这个因子意味着：**情绪越强烈，对自信的影响越大**。
平静时（S=15）的影响只有强烈时（S=100）的 15%。

**② 偏离越大推力越强（指数曲线）**

```
gain = 1.0 × e^(1.5 × dev)

dev = 0    → gain = 1.0
dev = 0.5  → gain = 2.1
dev = 1.0  → gain = 4.5
```

意思是：L 已经在高位时，快乐会把它推得更高（滚雪球）；L 已经在低位时，恐惧会把它压得更低。
**这是刻意的**——人的自信崩掉是加速的，恢复也是加速的。

**③ 允许推到极限**

L 不做硬性限位（只 clamp 到 0~100），靠三路力量自己平衡：

- 记忆基线拉回
- 时钟回落
- SC 推出去

所以理论上 L 可以接近 0 或 100，但会持续被拉回。

### L 反过来影响什么

| 影响 | 说明 |
|---|---|
| 说话量 | `L > 60` → 话痨；`55 < L ≤ 60` → 好奇；`L ≤ 55` → 安静 |
| 语气 | 提示词里描述自信程度 |
| 语音语调 | 语音合成时语速/音调随之变化 |
| 安全阀 | L 过低/过高是五个监控条件中的两个 |

### 与情绪自制器的区别

| | SC 系统 | 情绪自制器 |
|---|---|---|
| 触发 | 每轮都算 | S ≥ 75 且不在冷却 |
| 作用对象 | 只改 L | H / S / L 三个都改 |
| 方向 | 把 L 推离中心 | 把三个都拉回基线 |
| 目的 | 让情绪影响自信 | 防止情绪卡在极限 |

一个推出去，一个拉回来——两者共同让 L 既敏感又不会失控。

## 2.7 HSL 引擎在系统里的位置

```
        ┌──────────────────────────────┐
        │        HSL 情绪引擎           │
        │  H 色相 / S 强度 / L 明度      │
        └───┬────────┬────────┬────────┘
            ↑        ↑        ↑
    ┌───────┘   ┌────┘   ┌────┘
    │           │        │
  对话情绪    视觉情绪   听觉情绪
    │           │        │
    └───────────┴────────┘
            ↓
     记忆的价值公式（S_α 参与 γ 计算）
            ↓
     回复的语气、语音的语调
```

**关键点**：HSL 不是独立的装饰模块——它的 S 值直接参与记忆价值计算（见第三章）。也就是说：**AI 在什么情绪下看到的东西，会影响那段记忆有多重要**。

## 3.0 三个大区的总览

| 大区 | 分区数 | 存什么 | 特殊之处 |
|---|---|---|---|
| **语义记忆区** | 8 | 对话、知识、日记、人物、前世 | 四戳最完整，有生活/知识分流 |
| **视觉记忆区** | 7 | 画面描述 + 关键帧 | 有周更池（连续剧），Ⅱ区压缩 |
| **听觉记忆区** | 4 | 转写文本 + 指纹/声纹 | 少两层，缓冲池一次给 72 小时 |

**每个分区 = 一个独立的数据库文件**，在 `data/zones/` 下。

## 3.1 语义记忆区（文本）

### 工作范畴

存所有「说出来的」和「读到的」东西：对话内容、日记、人物信息、知识、前世记忆。

### 八个分区

```
上下文（2h）→ 快池（2h）→ 观察池（24h）→ 保留池（72h）
                                            ├─ δ₁ ≥ 1.2 或 钉住 → 生活区
                                            └─ δ₁ ≥ 0.8 → 知识区
                                                 其余 → 遗忘

生活区（90 天到期）→ 钉住 或 δ₂ ≥ 1.0 → 冷存
                    → δ₂ ≥ 0.6 → 延寿 30 天
                    → 其余 → 遗忘

知识区（120 天到期）→ 钉住 或 δ₂ ≥ 0.8 → 冷存
                    → δ₂ ≥ 0.5 → 延寿 30 天
                    → 其余 → 遗忘

冷存：只压缩，永不遗忘

前世记忆区（24h）→ 快池（导入的旧记忆）
```

### 功能

| 功能 | 怎么运作 |
|---|---|
| **记住** | 写完立即进上下文区 |
| **淡忘** | 72 小时内没被用到就遗忘 |
| **变重要** | 每被真正用到一次，δ +1 |
| **进冷存** | 生活/知识区到期时，δ 够高就永不遗忘 |
| **检索** | 向量 + 时间 + 情绪三路 |

### 工作模式

**四枚情绪戳**是核心：

| 戳 | 全名 | 作用 |
|---|---|---|
| **α** | 编码时 AI 的情绪 | 记住「AI 当时是什么心情」 |
| **β** | 内容本身的情绪 | 记住「这件事本身是什么情绪」 |
| **γ** | 清醒度 / 鲜明度（0~1） | 这条记忆有多清晰 |
| **δ** | 价值戳（分 δ₁ 缓冲 / δ₂ 长期） | 这条记忆值不值得记 |

```
α + β → 决定 γ（记不记得清）
δ     → 决定值不值得记
```

γ 的算法：

```
αβ 重合度 = 0.6 × 色相相似度 + 0.4 × 饱和度相似度
δn       = 1 − exp(−δ / 5)
γ        = (αβ重合度 + (1 − αβ重合度) × 0.3 × δn) × (0.7 + 0.3 × sensory)
```

δ 的双段：

```
δ₁（缓冲池）：每 3 小时 ×0.95
δ₂（生活/知识区）：每 30 天 ×0.7
```

### HSL 引擎环节

| 环节 | HSL 参与方式 |
|---|---|
| 写入 | 记录 α（当时的 H/S）|
| 价值 | α 与 β 的相似度决定 γ |
| 检索 | 情绪相似度是三个检索维度之一（权重 0.3）|
| 回忆 | 想起高 γ 记忆 → 情绪被拉回当时状态（记忆反哺）|

## 3.2 视觉记忆区

### 工作范畴

存「看到的」：桌面画面、视频内容、屏幕上的文字。

### 七个分区

```
视觉上下文（2h）→ 视觉快池（2h）→ 视觉观察池（24h）→ 视觉保留池（72h）
                                                      ├─ p₀ ≥ 1 或 δ₀ ≥ 1.2 → 视频Ⅰ区
                                                      └─ 其余 → 遗忘

周更池（192h，连续剧/番剧）→ 视频Ⅰ区

视频Ⅰ区（周期看类型：短片 10 天 / 系列 150 天 / 单集 180 天）
   ├─ p₀ ≥ 1 或 δ₀ ≥ 1.0 → 视频Ⅱ区
   ├─ 延寿（+0.4 喜好度，+30 天，每块只能延一次）
   └─ 到期 → 遗忘

视频Ⅱ区（长期）→ 按价值 V_Ⅱ 压缩
```

### 功能

| 功能 | 怎么运作 |
|---|---|
| **看见** | 截屏 → 描述 → 存一条记忆 |
| **留图** | 只有高变化帧才把图片复制进保护目录 |
| **淡忘** | 72 小时内没被用到 → 遗忘（连带删图）|
| **被抢救** | 到期前 AI 可以加 0.4 喜好度 + 延寿 30 天 |
| **压缩** | 进Ⅱ区后按价值决定留几张关键帧 |

### 工作模式

**价值公式**（视频）：

```
γᵥ = clamp(0.6 × (S_α/100 + 视觉模型评分), 0, 1)
γ₀ = 0.5γᵥ + 0.3γₐ + 0.2γₘ
δ₀ = 0.5×(0.6δᵥ + 0.4δₐ) + γ₀
p₀ = pᵥ + pₐ          （pᵥ = 0.4x, pₐ = 0.4y, x≥0, −0.5≤x+y≤4）
V_Ⅱ = 2.5γ₀ + 3.5p₀ + 4δ₀
```

**喜好度 p₀ 从哪来**：

| 来源 | 什么时候 | 幅度 |
|---|---|---|
| AI 看视频时 | 每个画面 | 视觉模型给 0~1 分 |
| AI 到期前抢救 | 保留池 72h 窗口 | +0.4（每块只能一次）|
| 用户评价（AI 代判）| 用户说喜欢/一般 | like +0.4 / normal +0.1 / 弃权 0 |
| 行为信号 | 重复播放 / 静态画面 | +0.2 / −0.2 |

**Ⅱ区压缩**：

| V_Ⅱ | 处理 |
|---|---|
| ≥ 3 | 保留关键帧 + 摘要 |
| 1 ~ 3 | 摘要 + 1 枚关键帧 |
| 0.3 ~ 1 | 只留摘要（不要图）|
| < 0.3 且停留 > 2 年 | 遗忘 |

### HSL 引擎环节

| 环节 | HSL 参与方式 |
|---|---|
| 写入 | S_α（AI 当时的饱和度）直接进 γᵥ 公式 |
| 价值 | **AI 在什么情绪下看到画面，决定这段记忆有多重要** |
| 搭话 | L 值决定搭话概率（L 低 → 少说话）|
| 反馈 | 看到的内容 → 推动 HSL |

## 3.3 听觉记忆区

### 工作范畴

存「听到的」：人声（转写 + 声纹）、音乐（指纹 + 标签）、环境声（标签）。

### 四个分区

```
听觉上下文（2h）→ 音频缓冲池（72h）→ 音频Ⅰ区（1h）→ 音频Ⅱ区（长期）
```

比视觉少两层（没有快池/观察池），因为声音是连续流，一次给足 72 小时。

### 功能

**音频缓冲池的三个职责**：

| 职责 | 说明 |
|---|---|
| **去重** | 同一首歌循环播放，不反复写记忆 |
| **筛噪音** | 纯噪音/静音直接丢弃 |
| **匹配情绪戳** | 音频情绪与 AI 当时情绪匹配后才写入 |

**音频Ⅰ区的分拣**：

| 类别 | 压缩后存什么 | 再次遇见 |
|---|---|---|
| **音乐** | 音频指纹（约 1 KB）+ 标签 + 情绪 | 指纹匹配 → 想起是哪首 |
| **人声** | 说话人声纹（约 2 KB）+ 转写文本 | 声纹匹配 → 认出是谁 |
| **环境声** | 场景标签（几个词） | 标签匹配 |

### 工作模式

**价值公式**（音频，权重偏音频）：

```
γ₀ = 0.2γᵥ + 0.6γₐ + 0.2γₘ
δ₀ = 0.5×(0.2δᵥ + 0.8δₐ) + γ₀
p₀ = pᵥ + pₐ
```

### HSL 引擎环节

| 环节 | HSL 参与方式 |
|---|---|
| 写入 | S_α 进 γₐ 公式 |
| 情绪 | 音频情绪（emotion2vec）与 AI 情绪匹配 → 决定是否写入 |
| 音乐 | 听音乐时 HSL 实时受影响（同视频逻辑）|

# 四、视觉系统独立工作流

## 4.0 鼠标巡逻（快速划鼠标 → 看一眼）

桌面监视开着时，如果你在一块区域里快速划鼠标超过 3 秒，AI 会看一眼那块区域。

**为什么需要这个**：日常监视是「按时间轮询」，很多重要操作只持续几秒（选文件、拖窗口、找菜单）——轮询很容易错过。鼠标快速移动往往意味着「我正在这儿干活」，这是最可靠的注意力信号。

### 触发条件

| 条件 | 判定 |
|---|---|
| **速度快** | 瞬时速度 ≥ 260 像素/秒 |
| **在一块区域内** | 最近 4 秒轨迹的包围盒 ≤ 900×700（全屏乱飞不算） |
| **持续 3 秒** | 快速移动连续累计满 3 秒 |
| 慢下来 | 快速计时按 2 倍速衰减（不是立即清零） |

### 截哪里

```
轨迹包围盒
  ↓ 向外扩 60 像素（"及周围"）
  ↓ 保证最小 220×220（太小看不清）
  ↓ 夹在屏幕内
  ↓ 与前台窗口取交集
有窗口 → 按窗口截（更贴合你在做什么）
没窗口 → 按扩展后的区域截
```

### 冷却：3~5 分钟，动态

不是一直看。触发一次后进入冷却，时长由两个因素决定：

| 因素 | 影响 |
|---|---|
| **内容重复**（和上次描述相似度 ≥0.6，即在重复同一件工作） | +2 分钟 |
| **L 值低**（<40，消沉/不自信） | +1 分钟 |

```
基础 180 秒
+ 重复工作 120 秒
+ L 低      60 秒
上限 300 秒（5 分钟）
```

**为什么这样设计**：

- **重复工作冷却长**：你在同一个编辑器里连续改代码，没必要反复看
- **L 低冷却长**：低落时不需要频繁打扰，少看几次

### 状态查询

采集管理器的状态里带巡逻信息：

```json
{
  "patrol": {
    "running": true,
    "triggered": 2,
    "cooldownLeftMs": 145000,
    "fastMs": 1200,
    "samples": 2400
  }
}
```

| 字段 | 含义 |
|---|---|
| `triggered` | 累计触发次数 |
| `cooldownLeftMs` | 剩余冷却时间 |
| `fastMs` | 当前累计的"快速时长"（到 3000 触发） |
| `samples` | 收到的坐标样本数 |

## 4.1 完整链路

```
① 采集合成
   截屏（分辨率 = 变化率 × L 双重决定）
     · 低变化帧基准 336px / 高变化帧基准 448px
     · 再乘 L 缩放系数（L=0→0.8，L=50→1.0，L=100→1.2）
     · 实际范围：低信息 269~403px，高信息 358~538px
   视频窗口 → 只截视频区域（ROI）
        ↓
② 帧级漏斗
   帧差计算 → 10 秒一段 → 段内按密度分配 → 挑 top-K
        ↓
③ 去重
   aHash 相似度 ≤ 5 → 跳过（不重复送模型）
        ↓
④ 描述（一个模型全包）
   Qwen2.5-VL-3B（约 3.2 GB 显存，只在看屏幕/看视频时拉起）
   精看和 OCR 都交给它，不再有 SmolVLM「快看」这一层
        ↓
⑤ 看不清就放大
   描述含「看不清/模糊」→ 居中裁剪 50% → 再问一次
   放大后的宽度 = 1280 × L 缩放（1024 ~ 1536px）
        ↓
⑥ 可选补充
   高优先级帧 → HSEmotion（人脸情绪，8 类）
   画面氛围 → VibeNet
        ↓
⑦ 需要认字
   Qwen2.5-VL-3B 顺带 OCR（不另装模型）
        ↓
⑧ 写视觉记忆
   算 γ₀ / δ₀ / p₀ → 进视觉上下文区
        ↓
⑨ 云端兜底（极少）
   连续失败 2 次 → 才考虑发合成故事板
        ↓
⑩ 感知调度
   变化率 → 调整下一次截屏间隔（2~30 秒）
   主进程统一决策，采集层只执行
```

### 汇总：交给 OmniDimen 整理成一句话

视觉和听觉各自出结果后，不是直接写记忆，而是先汇总：

```
画面描述 + 人脸表情 + 声音描述 + 音乐情感 + 指纹
    ↓
简单场景（只有一边、文本短）→ 直接拼接，不调模型
复杂场景（两边都有、信息多）→ OmniDimen 整理成一句自然描述
    ↓
模型不可用 → 退回拼接（信息不丢）
    ↓
写记忆
```

**提示词约束**：只输出 1~2 句、第一人称、保留关键信息（谁/在哪/在做什么/听到什么）、不编造；语气按 L 调（L 低安静简短、L 高轻快）。

**什么时候才上云**：只有「本地整理失败」或「信息量超过 1200 字」才考虑，而且还要过云端闸门（日 5 次、时 1 次、连续失败 2 次）。

## 4.2 各模型分工

| 模型 | 端口 | 分工 | 显存 | 什么时候在 |
|---|---|---|---|---|
| **Qwen2.5-VL-3B** | 8091 | 看屏幕 / 看视频 / 深描 / OCR（全部视觉判断） | 3.2 GB | 视觉开关打开时按需拉起 |
| **HSEmotion B0** | — | 人脸情绪（8 类）| CPU | 高优先级帧 |
| **VibeNet** | — | 画面氛围/色调 | CPU | 可选 |

**为什么只留一个视觉模型**：SmolVLM2-500M 当初是为了省显存做「快看」，但它描述不准（"画面全黑"这类误报很多），
而且 8 GB 卡上它和 Qwen2.5-VL 从不同时在跑，省下来的显存没有实际收益。退役后链路简单一半：截屏 → 帧差 → Qwen2.5-VL → 写记忆。

## 4.3 HSL 引擎环节

| 环节 | HSL 参与 |
|---|---|
| ④ 描述 | 模型的喜好分 + **AI 当前 S 值** → 算 γᵥ |
| ⑧ 写记忆 | S_α 记录进记忆 |
| ① 采集 | **L 影响截图分辨率**（L 低省资源、L 高清一些）|
| ⑩ 调度 | L 值影响搭话权限（L 低时几乎不主动说话）；L 也影响抽帧率（0.2~1.0 fps）|
| 反馈 | 看到的画面情绪 → 推动 HSL 的 H/S |

## 4.4 视频文件分析（另一条路）

```
ffmpeg 镜头切分（按画面变化找切点）
    ↓
按覆盖度选 4~16 个代表时间点
    ↓
按时间点抽帧（480px 宽）
    ↓
拼成九宫格（省 token）
    ↓
Qwen2.5-VL-3B 概括
    ↓
存一条视频记忆
```

注意：这条只用于「用户主动给一个视频文件」，实时看视频走 4.1 的链路。

# 五、听觉系统独立工作流

## 5.1 完整链路

```
① 采集（三种方式，按场景自动选）
   · 看视频时 → **按进程回环**：只抓浏览器/播放器这个进程的声音，
                 不混入你说话、通知音、其它程序
   · 一般情况 → 系统回环：抓系统混音（会混入其它声音）
   · 视频文件 → 直接抽音轨（最干净，不碰声卡）
        ↓
② 先判断「这是什么声音」
   PANNs CNN14 → 527 类 AudioSet 标签 → 翻译成 11 类中文声源
   （人声 / 音乐 / 警报 / 键鼠 / 碰撞 / 车辆 / 自然 / 动物 / 人群 / 机器 / 噪声）
        ↓
③ 按分量决定跑哪些模型（协同，不是二选一）
   ┌─ 有人声分量 → 转写 + 情绪 +（指纹，唱歌场景）
   ├─ 有音乐分量 → 音乐情感 + 指纹
   ├─ 两个都有   → 都跑（标为「影视音」，对白 + 配乐）
   └─ 都没有     → 不跑重模型，直接出一句「这是什么声音」
        ↓
④ 缓冲池处理
   去重（同一首歌/同一段环境声不反复写）
   筛噪（纯噪音丢弃）
   情绪戳匹配（音频情绪 vs AI 情绪）
        ↓
⑤ 进融合器（等同一时间窗的画面一起合并）
        ↓
⑥ 写听觉记忆
   算 γ₀ / δ₀ → 进听觉上下文区
```

### 按进程采集是怎么做到的

用 Windows 的「应用回环」（Application Loopback）：

```
1. 拿默认输出设备（MMDeviceEnumerator）
2. 构造激活参数：{ 目标进程ID, 模式 = 包含整个进程树 }
3. 包进 PROPVARIANT（VT_BLOB）传给 IMMDevice::Activate
4. 拿到 IAudioClient → 初始化（共享模式 + LOOPBACK 标志）
5. 循环读帧 → 混成单声道 → 降到 16k → 存 wav
```

**关键坑**：不能用 `ActivateAudioInterfaceAsync`——它不支持复杂的进程过滤参数，
会一直报错。必须用 `IMMDevice::Activate`。

**实测隔离效果**：目标进程放 660Hz、另一个进程放 2600Hz，
录到的过零率是 1323/秒（正好是 660×2）——说明只抓到了目标进程的声音。

### 声音分成 11 类

| 类别 | 例子 | 跑不跑重模型 |
|---|---|---|
| **人声** | 说话、窃窃私语、小孩 | ✅ 转写 + 情绪 + 声纹 |
| **音乐** | 流行、钢琴、电子 | ✅ 音乐情感 + 指纹 |
| **影视音** | 对白 + 配乐（看视频） | ✅ 两个都跑 |
| 警报 | 闹钟、蜂鸣、错误音 | ❌ 只给描述 |
| 键鼠 | 打字、点击 | ❌ |
| 碰撞 | 敲击、重物落地 | ❌ |
| 车辆 | 引擎、喇叭 | ❌ |
| 自然 | 雨、风、鸟 | ❌ |
| 动物 | 狗叫、猫叫 | ❌ |
| 人群 | 嘈杂、笑声、鼓掌 | ❌ |
| 机器 | 风扇、打印机 | ❌ |
| 噪声 | 底噪、静电 | ❌ |

**为什么这样分**：键盘声、警报声不需要转写也不需要情绪分析——它们只要一句「这是什么」就够了。只有当声音里有人或音乐时，才值得动用重模型。

### 协同：对白和配乐同时存在

看视频时最常见的场景就是「有人说话 + 背景音乐」。旧实现是二选一（判成音乐就不转写），会丢掉台词。

现在改成**分别判断两个分量**：

```
hasVoice = 标签里有 speech/male/female/singing…
hasMusic = 标签里有 music/piano/guitar/melody…

两个都真 → 两个模型都跑 → 描述合成：
  「有人说话：「你好啊，好久不见」，语气高兴，在放音乐（偏明快、中等），认得这首」
```

### 错峰：显存不够时排队

视听两条链路会同时想跑模型，8 GB 卡装不下 → 走同一条队列：

```
优先级：视觉精看(10) > 视觉快看(20) > 转写(30) > 情绪(40) > 音乐(50) > 环境声(60)
并发：1
```

实测：视觉精看 + 转写 + 情绪同时提交 → 按优先级串行，不会同时抢显存。

### 合并：同一时间窗的画面和声音

```
窗口 8 秒
视觉结果 → 缓冲（带时间戳）
听觉结果 → 缓冲（带时间戳）
窗口结束 → 配对：
  · 都有   → 合成一条「联合记忆」
  · 单边   → 单独成条（不丢）
  · 同侧多条 → 合并描述（都保留）
```

这样「看视频」不会被拆成两条互不相关的记录，而是「同一时刻发生的同一件事」。

## 5.2 各模型分工

| 模型 | 分工 | 速度 |
|---|---|---|
| **Qwen3-ASR-0.6B**（CrispASR） | 转写文本 + 标点，自带 VAD 切段 | **15.3x 实时**（78 秒音频 5.1 秒） |
| **emotion2vec+** | 语音情绪（高兴/悲伤/愤怒等）| 几十毫秒/段 |
| **PANNs CNN14** | 环境声/音乐分类 | 快 |
| **ECAPA-TDNN** | 声纹（192 维，认人）| 快 |
| **Chromaprint** | 音乐指纹（约 1 KB/首）| 极快 |
| **DSP**（`lib/audio/dsp/`） | BPM / 调性 / 和弦 / 段落结构 / 情绪曲线 | 0.3 秒，不花推理 |

> **为什么换掉 SenseVoice**：同一段 78 秒音频，SenseVoice 要 26.4 秒（3x 实时）且几乎不输出标点，
> 同音字错误多（「六刀全中」→「六刀拳中」），结尾还会冒出「う。The.」这类幻觉。
> Qwen3-ASR 5.1 秒跑完，标点齐全，配合 `--context` 热词能把人名、术语识别对（「先看人生」→「先看**人声**」）。
> FSMN-VAD 一并退役——CrispASR 内部会切段。

## 5.3 HSL 引擎环节

| 环节 | HSL 参与 |
|---|---|
| ③ 情绪识别 | emotion2vec 结果 → 推动 HSL |
| ④ 匹配 | 音频情绪与 AI 当时情绪匹配 → 决定写入权重 |
| ⑤ 写记忆 | S_α 进 γₐ 公式 |
| 反馈 | 听音乐时的情绪 → HSL 实时变化 |

## 5.4 语音输出链路

```
AI 回复文本（流式生成中）
    ↓ 监听 agent/assistant-stream：凑满一句就送去合成
CosyVoice3（0.5B，常驻 server 8099）
    参数：情绪 → 挑音色；L + S → 语速
      · S 高（情绪激动）→ 语速陡增；S 低 → 平稳
    逐句合成（热态 ~0.7~0.95 秒/句）
    ↓
ffplay 播放（-volume 读菜单音量；-af atempo 边播边变速）
    ↓
可被长按打断
```

要点：

- **常驻服务而不是每次起进程**：CLI 每次合成都要重新加载 0.5B 模型（~10 秒），改成常驻后首句 ~0.9 秒出声；
- **流式接文本**：不等整段回完，模型吐到句号就开始合成，首句提前 1~3 秒；
- **空闲 10 分钟自退**，关语音输出 / 关 exe / 休眠都会停，不白占显存；
- **不会念英文 AI 声明**：服务端模式对克隆音色会强制加一句英文免责声明，所以默认走内置音色（无声明）；配了克隆音色时改走 CLI（能用 `--no-spoken-disclaimer`，但慢一些）。

### 音色克隆（给其他用户）

```
把音频丢进 data/voices/incoming/（wav / mp3 / m4a / flac / ogg）
  ↓ 可选：同目录放同名 .txt 写它说的内容（更准）
启动时自动导入 → 转 24k 单声道 → 没有台词就用 ASR 转写
  ↓
生成 data/voices/<名字>.wav + .txt，原文件归档到 incoming/done/
  ↓
voice.json 里 mode=clone、wav 指向它，即成为默认音色
```

手动导入：`node plugin/lib/tts/import-voice.mjs`

## 5.5 语音输入（对讲机模式）

```
用户长按悬浮球（600ms）
    ↓
① 立刻打断正在播放的语音
    ↓
② 开始录音，每 2 秒一段
    ↓
③ 累积拼成完整音频，每次都送整段识别
   （重叠识别，不会把词切断）
    ↓
④ 松开 → 用完整音频再识别一次（最准）
    ↓
⑤ 识别结果注入对话
```

**为什么这样设计**：分段识别会把词切断（「今天天气」+「不错」），累积识别保证「从开始到现在的整句话」总是完整的。

# 六、视觉、听觉联合工作流

## 6.1 什么时候需要联合

单看画面或单听声音都会缺信息：

| 场景 | 只看画面 | 只听声音 |
|---|---|---|
| 看视频 | 知道画面，不知道台词/音乐 | 知道台词，不知道谁在做什么 |
| 视频通话 | 看到脸，不知道说什么 | 听到声音，不知道表情 |
| 玩游戏 | 看到画面，不知道剧情语音 | 听到音效，不知道画面 |

## 6.2 联合链路

```
         画面                      声音
          ↓                         ↓
   Qwen2.5-VL-3B            Qwen3-ASR + emotion2vec
          ↓                         ↓
     画面描述文本               台词 + 声音情绪
          ↓                         ↓
          └────────┬────────────────┘
                   ↓
            ① 时间对齐
            同一时间窗（±30 秒）内的画面与声音配对
                   ↓
            ② 情绪融合
            画面情绪（γᵥ）+ 声音情绪（γₐ）→ 合成 γ₀
            γ₀ = 0.5γᵥ + 0.3γₐ + 0.2γₘ   （视频记忆）
                   ↓
            ③ 信息量融合
            δ₀ = 0.5×(0.6δᵥ + 0.4δₐ) + γ₀
                   ↓
            ④ 写一条联合记忆
            文本 = 画面描述 + 台词摘要
            avMeta = { 关键帧, 音频指纹/声纹 }
                   ↓
            ⑤ 三路检索可同时召回
            时间邻近（0.3）+ 情绪相似（0.3）+ 向量相似（0.4）
```

## 6.3 HSL 引擎环节

联合场景下 HSL 受影响最大：

```
看到激烈画面 → H 偏红、S 升高
听到紧张音乐 → S 再升高
两者叠加 → 可能触发情绪自制器（S ≥ 75）
        → 或触发安全阀（S 持续过高）
```

**这就是为什么需要联合**：单独看画面或单独听声音，情绪推动都不够真实；两者叠加才像「真的在看一部电影」。

## 6.4 跨区检索（三区串联）

```
查询（任意来源）
    ↓
① 时间邻近：同窗口 ±30 秒
② 情绪相似：β/γ 的 H/S/L 距离 < 阈值
③ 向量相似：Qwen3-Embedding 语义
    ↓
三路取并集 → 联合排序 → 返回跨区记忆
```

| 信号 | 权重 |
|---|---|
| 时间邻近 | 0.3 |
| 情绪相似 | 0.3 |
| 向量相似 | 0.4 |

**效果**：同一件事（画面 + 声音 + 对话）能被一次检索同时召回。

# 七、分流层工作范畴

## 7.1 分流层是什么

挂在一个语言模型调用接口上，决定「这个请求要不要花云端 token」。

```
请求进来
    ↓
① 语义缓存查（Qwen3-Embedding 向量相似度 ≥ 0.88）
   命中 → 直接返回历史答案（0 token）
    ↓ 没命中
② 复杂度判断
   ├ 简单（问候 / 格式化 / 复述 / 短翻译）→ Qwen3-1.7B 本地生成（0 token）
   └ 复杂 → 放行云端，同时旁路写缓存
```

> Qwen3-1.7B 全面顶替了 0.6B：路由分类实测 12/15（0.6B 只有 7/15，且系统性把 cloud 判成 local），
> 摘要质量也明显更好。代价是慢约 2.4 倍——它在 CPU 上跑，不占显存，所以这个代价可以接受。

### 总闸门：只看「本地分流」开关

分流层是可选组件，**开关关着就完全不介入**——不查缓存、不本地生成、直接放行云端。

以前这里只检查插件总开关，于是出现「本地分流明明关着，HCEM 却还在用本地模型、反复同一句话」：因为缓存和本地生成照常工作。现在：

| 开关 | 分流层行为 |
|---|---|
| 本地分流 = 开 | 查缓存 → 判复杂度 → 本地/云端 |
| 本地分流 = 关 | 直接放行云端（缓存也不查） |
| 主动说话那一轮 | 若分流开着，强制走本地（不烧云端额度） |

## 7.2 各模型分工

| 模型 | 分工 | 成本 |
|---|---|---|
| **Qwen3-Embedding-0.6B** | 语义缓存 / 记忆检索 / 工具目录检索（1024 维）| 本地，**CPU 常驻，不占显存** |
| **Qwen3-1.7B** | 分流分类 + 感知摘要第一步 + 梦的抽卡 | 本地，CPU |
| **OmniDimen-4B** | 情绪判定 / 编梦 / 自评（每个请求都要过）| 本地，GPU ≈2.7 GB |
| 云端模型 | 复杂请求 | 花 token |

> Embedding 从 GPU 挪到 CPU：单条 63 ms（GPU 50 ms），换回 1.1 GB 显存——8 GB 卡上这笔账更划算。

## 7.3 保守原则

只拦「确定云端无额外价值」的请求：

| 拦 | 放行 |
|---|---|
| 问候（「你好」「在吗」）| 任何需要推理的问题 |
| 格式化（「换成列表」）| 需要知识的回答 |
| 复述（「刚才说了什么」）| 需要创造的内容 |
| 短翻译（几个词）| 长文本翻译 |

宁可多花一点 token，也不让回答质量下降。

## 7.4 语义缓存规格

| 项 | 值 |
|---|---|
| 相似度阈值 | 0.88 |
| TTL | 7 天 |
| 容量 | 500 条 |
| 用户纠正 | 可删除对应条目 |
| 存储 | `data/semantic-cache.jsonl` |

## 7.5 HSL 引擎环节

分流层对 HSL 的影响是间接的：

- 简单请求用 Qwen3-1.7B 时，**情绪判定仍由 OmniDimen 做**（不省这一步）；
- 缓存命中的回答，情绪推动照常计算（避免「重复问同一句话情绪不动」）。

# 八、完整全模型工作流

## 8.1 一轮完整对话

```
【用户输入】
打字 或 长按悬浮球语音输入
    ↓
【① 语音转文字】（如果是语音）
Qwen3-ASR（CrispASR）→ 文本（带标点）
    ↓
【② 分流层】
Qwen3-Embedding 查缓存 → 命中直接返回
    ↓ 没命中
Qwen3-1.7B 判复杂度 → 简单请求本地生成
    ↓ 复杂请求
【③ 语义分析】
OmniDimen-4B：这句话是什么情绪、什么意图
    ↓
【④ 检索记忆】
Qwen3-Embedding 向量 + 时间邻近 + 情绪相似
    → 从三大区召回相关记忆
    ↓
【⑤ 情绪结算】
HSL 引擎：新情绪 = 旧情绪 + 对话刺激 + 记忆反哺
    ├ 检查自制器（S ≥ 75？→ 回调）
    └ 检查安全阀（五条件？→ 预警/停写/中止）
    ↓
【⑥ 生成回复】
OmniDimen-4B 带着情绪倾向生成
    ↓
【⑦ 写记忆】
算 α / β / γ / δ → 进语义记忆区上下文
    ↓
【⑧ 语音输出】
CosyVoice3 合成（L 调语速语调）→ 播放
    ↓
【⑨ 更新情绪显示】
悬浮球颜色实时变化
```

## 8.2 感知后台（并行运行）

```
【视觉循环】每 2~30 秒（按变化率）
截屏 → 帧差 → 漏斗 → Qwen2.5-VL → 写视觉记忆
    ↓ 有变化 → 更新「最近画面描述」
    ↓ 判断是否该搭话

【听觉循环】每 8~60 秒（按变化率）
录 5 秒 → Qwen3-ASR/emotion2vec/PANNs → 写听觉记忆
    ↓ 有人说话 → 更新「最近音频」
    ↓ 是音乐 → 后台补跑 BPM/调性/和弦/段落 + 音乐情感

【存储管家】每小时
清理临时文件（截屏 30 分钟 / 录音 24 小时 / 合成语音 2 小时）
清理保护目录孤儿文件
总量闸门（超过 2 GB 按最旧删）

【梦系统】空闲够久时
抽卡 → 编梦 → 自评 → 写日记
```

# 九、UI 功能介绍

## 9.1 三个窗口 + 两个 DSH 内建入口

HCEM.exe 自己只有三个窗口（每个窗口 = 一组 WebView2 进程，用不到的不建）：

| 窗口 | 大小 | 作用 |
|---|---|---|
| **悬浮球**（orb） | 200×200，可缩放 | 常驻桌面，显示情绪色彩，拖动 / 长按说话 / 右键 |
| **菜单**（menu） | 默认 900×660，可记忆 | 6 个页面，所有设置与开关 |
| **快捷菜单**（ctx） | 120×240 | 右键球弹出的 6 个快捷入口 |

嵌入在 DSH 里的入口（由客户端插件提供，不占 HCEM 进程）：

- **状态栏「搭话度」按钮**：话痨 / 好奇 / 安静，点开三选一
- **语音通话按钮**：只在 HCEM 会话显示，点开就是通话模式

> 旧的「对话窗」已删除（聊天统一在 DSH 会话里，独立输入框做不到和会话同步）。

## 9.2 悬浮球

### 外观

- 液态玻璃球，内部是 SVG 遮罩的液体流动效果；
- **颜色实时反映 HSL**：H 决定色调、S 决定鲜艳度、L 决定亮度；
- 三层光环（模糊 3/7/14/22px），随 S 值变亮。

### 操作

| 操作 | 效果 |
|---|---|
| 左键单击 | **不动作**（主入口是右键） |
| 长按 600ms 以上 | 语音输入（对讲机模式），松开提交 |
| 短按（<600ms） | 取消这次录音，什么都不弹 |
| 按住拖动 | 移动位置（位置会被记住） |
| 右键 | 打开快捷菜单（球左侧） |

> 悬浮球**不可拖边缘缩放**（那会把左键吃掉），大小固定 200×200；要调整用菜单里的「悬浮球大小」滑杆（0.5~2.0 倍）。

## 9.3 菜单（6 个页面）

### ① 角色卡

- 人格设定：名字、身份、说话风格
- 三个性格滑块：温和度 / 包容度 / 乐观度（范围 ±5）
- 性格影响 HSL 基线：

```
H 基线 = 30 + 乐观度 × 2.0
S 基线 = 15 + 温和度 × 0.45 − 包容度 × 0.15 + 搭话度修正 × 0.6
L 基线 = 55 + 温和度 × 0.15 + 包容度 × 0.08 + 乐观度 × 0.12 + 搭话度修正 × 0.5
```

- 保存后立即应用到悬浮球颜色

### ② 记忆导入

- 拖入记忆文件 → 复制到 `data/reincarnation/`
- 显示导入状态
- 用于「前世记忆」迁移

### ③ HSL 引擎

- 实时显示当前 H / S / L（色相环 + 数值）
- 手动调整情绪（拖动色相环）
- 显示情绪历史曲线
- 显示安全阀状态（五条件哪个触发了）

### ④ 日程 / 时段

- 设定不同时段的搭话度
- 例如：白天「好奇」、晚上「安静」
- 到点自动切换

### ⑤ 多模态

- 桌面监视 / 视频分析（合并为「视觉」一个开关）
- 音频监听开关
- 语音输出开关（TTS 常驻服务）
- 本地分流开关（qwen3 + omni 本地接话）
- 搭话度档位（话痨 / 好奇 / 安静）
- **模型检测**：逐个列出视觉 / 分流 / 向量 / 情绪 / 语音识别 / Python / 语音通道 / 显存，三态显示
  - ✓ 运行中（端口在听）
  - ○ 就绪未启用（模型在、开关没开）
  - ✗ 不可用（文件缺失/端口起不来）
- 手动启停模型服务

#### 开关和实际状态是同步的

菜单上的按钮不是"点一下就永远亮"：

- 打开开关 → 插件按开关拉起模型（显存不够时先让位，见 1.3 ⑧）
- 关掉开关 → 模型立刻停
- **显存让位把某个模型踢掉时，对应按钮会跟着变回「启动」**（插件写 evicted.json → pipe-server → Rust → 菜单）
- 菜单重新打开时也会主动向插件拉一次真实开关状态，避免"显示开着其实早停了"

#### 检测按钮

检测只**报告**状态，不启动模型。点一次约 1~2 秒（会查端口、进程、nvidia-smi）。

- 插件总开关
- 数据目录路径
- 日志查看
- 关于 / 版本信息
- 检查更新

## 9.4 会话窗口（在 DSH 里）

聊天不再是 HCEM 自己的窗口，而是 DSH 的会话页：

- 会话列表、消息记录、输入框都由 DSH 提供
- HCEM 在会话顶部挂两个入口：**搭话度按钮**（话痨/好奇/安静）和**语音通话按钮**
- 输入框上方的五条声波只在听话时出现

## 9.6 界面与后端的通信

```
界面（Rust 侧 WebView）
    ↓ 命名管道 \\.\pipe\hcem-bridge
    │  帧格式：[4 字节长度][1 字节类型][JSON]
    │  类型：STATE 状态 / CMD 命令 / ACK 应答 / LOG 日志 / PING-PONG 心跳 / HELLO 握手
    ↓
插件主进程（Node 侧）
    ↓
各模块（采集 / 记忆 / 模型 / 调度）
```

**为什么用命名管道而不是 HTTP**：不起服务器、不占端口、不监听网络——完全在本机进程间。

## 9.7 无控制台原则

所有后台进程都用 `CREATE_NO_WINDOW` 启动：

- 看不到任何 cmd / PowerShell 窗口；
- 不弹黑框；
- 日志写到 `logs/hcem-YYYY-MM-DD.log`（保留 7 天）。

## 10.1 `ui/src` 和 `data/ui-state` 的区别

这两个容易混，职责完全不同：

| | `ui/src/` | `data/ui-state/` |
|---|---|---|
| 是什么 | 前端**源码**（html/js/css） | 界面**运行时状态**（json） |
| 何时生效 | 改完要**重编 exe** | 改完**重启即生效** |
| 存放位置 | 编进 exe，运行时只读 | 磁盘，随时可写 |
| 能不能手改 | 能，但要重编 | 能，而且鼓励（调试用） |
| 会不会丢 | 换 exe 就换掉 | 跨重编/升级保留 |

之所以分开：exe 里的资源是只读的，而"开关/音量/音色"必须能写、要跨重编存活、还要能手动改 JSON 排查。

> 2026-11-21 从 `data/ui/` 改名为 `data/ui-state/`，并删掉了三个"只写不读"的死文件（`talk.json`/`sliders.json`/`hsl-base.json`）。

| 项 | 限制 |

| 音频指纹 | Chromaprint 只在工具里可用，还没接进主流程自动认歌 |
| 声纹 | ECAPA 可用，但人物卡绑定还没接 |

| 感知一轮要 60 秒 | `audioTick` 每次都要重新加载 panns/vibenet/emotion2vec，这是主要耗时 |
| 1.7B 摘要能力 | 路由分类够用，但写摘要时会偶尔加文学化发挥；靠 prompt 约束，没有硬性保证 |
| 断句 1400ms | 说话慢的人仍可能被切开；可在 `record_mic.py` 调 `SILENCE_MS` |
| 8 GB 显存 | Omni(2.7G) + 视觉(3.4G) + TTS(1.6G) 同时在线会顶满；已有准入让位，但同一时刻只能用其中两个 |
| 梦的首次启动 | 做梦前要拉起 qwen3 + omni 并等就绪，最坏等 60~90 秒；这段时间用户看不到反馈（只在日志里） |

| 笔记抽取 | 依赖 Qwen3（8093，CPU）；抽不到角色/背景时字段留空，不影响笔记本身 |
| 意图识别 | 目前是规则软识别；Commis 的意图头还没训练，误判按普通对话处理 |
| 种子扩展 | reasoning 路径只扩 1 跳 causal 边；没有因果边时退化为 top-3 |
| Omni 让位 | 看视频显存 >70% 会停 Omni；摘要第二步改走云端，但云端失败时这一轮不出评论 |

# 十五、2026-11-20 增补

这一轮主要是「语音打通 + 视听记忆落地 + 收尾」。详见 `docs/2026-11-20工作日志.md`。

## 15.1 语音通话

```
一直听（麦克风）
  ↓ 检测到开口（VAD onset）
立刻打断正在播报的 TTS
  ↓ 录到静音 1400ms 算一句
Qwen3-ASR 转写（带热词）
  ↓ 句子看着没说完（句尾无。！？）
再探一次「接着说」，最多接 2 次
  ↓
送进 HCEM 会话 → Omni 回答 → TTS 播报
```

**入口**：DSH 输入框上方的五条声波 + 挂断按钮（Client 插件），或 `hcem_voice` 工具。
**只对 HCEM 会话生效**，其它会话连图标都不显示。

打断是「停播放 + steer」，插件侧没有取消 turn 的 API，所以 AI 已经生成的内容不会撤回。

## 15.2 音乐分析

分两步，先便宜后贵：

```
每次听觉循环：PANNs 分类 → 是音乐？
  ↓ 是，且置信度 ≥ 0.35
后台补跑（不阻塞主循环）：
  DSP：BPM / 调性 / 和弦进行 / 段落结构 / 响度曲线
  VibeNet：音乐情绪
  ↓
合并成一句「听着是 C 大调、120 BPM、I-V-vi-IV 进行、偏温暖」
```

- 纯算法，0 次大模型推理，5 分钟音频约 0.3 秒
- **不做截断**：早期默认只取前 20 秒，结果 C 大调被判成 A 小调，现在全曲分析
- 静态音频（没有段落边界）会兜底成一个整段，避免丢 `lowBandShare` 等字段

## 15.3 两步感知摘要

```
perceptionWindow（最近 120 秒的「看到/听到」）
  ↓ 至少 3 条材料才跑（材料不够宁可不说）
第一步 Qwen3-1.7B：客观摘要「这段时间发生了什么」
  ↓
第二步 OmniDimen-4B：用 me + HSL + 随机记忆，讲成一段第一人称的话
  ↓
写 activation.json + 主动发进会话（与气泡共用 5 分钟闸门）
```

**注意**：记忆写入**不依赖**这段摘要。感知内容由 `onMerged` 直接写库，
即使 HCEM 一句话都没说，`video_observe` / `audio_context` 也会照常增长。

## 15.5 会话可靠性（踩过的坑）

DSH 的 `user/message` 事件数据就是一个 `UserMessage`，形状必须是：

```json
{ "id": "uuid", "role": "user", "content": [...], "source": {...} }
```

**少 `id` 会把整个会话判成 corrupt**：

```
stored session "..." is corrupt: session event at seq N lacks an identified message
```

这个坑踩了三次（seq 366 / 9 / 8）。`sendToSession` 现在一律带 `randomUUID()`，
并且 append 兜底复用同一个 payload。修会话的脚本留在项目根目录的 `.tmp/repair-session.mjs`（开发用，不入库）。

## 15.6 Python 环境独立

DSH 升级运行时时会把 `dsh-primary-runtime` 改名成 `.previous` 再装新的，
**旧运行时里的第三方包会一起消失**（pyaudiowpatch / numpy 全没了，录音直接挂）。

现在 HCEM 有自己的 venv：

```
python-venv/    numpy + pyaudiowpatch（63 MB）
```

`lib/audio/python.mjs` 按这个顺序解析：
`HCEM_PYTHON` 环境变量 → HCEM venv → `dsh-runtimes` 下可用运行时（跳过 `.previous`）→ PATH。

**不要**再把 Python 路径写死。

## 15.8 主动说话（气泡）

DSH 输入框下方状态栏有一个「冒泡·档位」按钮，点开三选一：**安静 / 好奇 / 话痨**。
它和 exe 菜单「角色卡」页的搭话度是**同一个字段**（`settings.json` 的 `talkativeness`），两边双向同步。

| 档位 | 触发间隔 | 说明 |
|---|---|---|
